# Gruff review: Phase 3E service hellos

Verdict: APPROVE WITH CHANGES (7 BLOCKING, 9 MINOR). Light rigour applied: every item below is a correctness issue, not ceremony.

## BLOCKING

1. BLOCKING, Sec 3 budget vs timing. Spec: six probes per silent port, 64 ports, 60 s. Evidence: `ActiveProbeBudget.step` adds each step's wall time to a summed counter (ActiveProbeBudget.kt:185-189) and up to 8 identifies run in parallel (ServiceIdentifier.kt:33). A silent port costs null 1.0 s + TLS 1.5 s + 6 x (connect + waitMs 1.5 s) = about 11 s. A 20-port host is about 220 s of summed time; the 60 s budget is gone after roughly 5 ports, which with 8 parallel workers is under 10 s of wall time. The rest of the host silently gets nothing and the result depends on scheduling. Also `entered` is a `HashSet<Int>` of port numbers (line 169), so "64 ports" means 64 distinct port numbers per scan across all hosts, not per host. Require: state the per-host and per-scan time model explicitly; separate wall-clock deadline from summed time; give the ladder a per-port wall cap (suggest 6 s) and a per-host cap; shorten `waitMs` for unhinted rare probes to 400 ms; define what a budget-starved port stores (it must keep the 3A result, not downgrade); key `entered` by host+port.

2. BLOCKING, Sec 3 step 2 and 6, TLS handling. Spec does a TLS peek on every silent non-`plainOnly` port, then re-sends every probe inside TLS. `plainOnly` is never defined. Each probe is a fresh connect plus fresh handshake: six full handshakes against an ESP32/ESP8266-class device exhaust heap and sockets (a common crash mode), and a ClientHello at a non-TLS embedded stack is itself a known hang trigger. 3A only did this on unknown ports in Full mode (ServiceIdentifier.kt:119-128). Require: define `plainOnly`; TLS-tunnelled probes limited to HTTP-family probes (and ports whose hint says TLS), not all 35; one handshake per ladder where possible; max 2 handshakes per port; STARTTLS ports (25/587/21/143) explicitly out.

3. BLOCKING, Sec 3 step 3 and 6, probe safety. "Every hello is read-only" is not true of the list as written. (a) Ladder sends all `safe` probes by rarity to unknown ports, including `smb-negotiate`, `mssql-prelogin`, `kafka-apiversions`, `zookeeper-ruok`, `adb-cnxn`, `socks5`: a binary protocol blob sent to an unrelated embedded listener (cameras, hubs, printers) is the classic crash vector; nmap has the same risk and mitigates with rarity and a 7 default intensity. (b) `postgresql-startup` with user `netprobe`, `mqtt-connect`, `ldap` bind, SNMP `public` and `amqp` all write auth-failure lines to server logs and can trip fail2ban or lockout counters; "careful" does not cover that. (c) MQTT CONNECT with clean session can kick a connected client id on brokers that enforce unique ids (client id `netprobe` is fixed, so low risk, but say it is random per run). Require: every non-text probe is hinted-only (`careful`), only text/ASCII and TLS/HTTP probes join the rarity ladder; remove the claim "read-only" in favour of "no state change, may be logged"; document the log footprint in the settings caption.

4. BLOCKING, Sec 3 step 5 and 7, UDP is incompatible with the data model. UDP is declared out of scope (Sec 1) then added (Sec 3). `PortEntity` has no protocol column (Entities.kt:44-50), so UDP 161 and TCP 161 collide on `(hostId, port)`, on `ServiceMerge`, on `ActiveProbeBudget.entered` and on `DeviceIdentifier` (`openPorts` keyed by Int). UDP has no open/closed signal on Android without ICMP, "answered TCP on nothing else of interest" is undefined, and a port that answers is an "open UDP port" scan result that nothing displays. Require: either cut UDP from 3E (my recommendation: SNMP is already the 3B tool) or add a `protocol` column in schema 5, change every key, and define the trigger precisely.

5. BLOCKING, Sec 4 data format cannot express half the initial probes. Missing: (a) dynamic substitutions (`{ip}`, `{port}`, `{localIp}`, random token) needed by sip-options, rtsp-options, http Host (HEAD uses `ip.hostAddress`, ServiceIdentifier.kt:70); (b) multi-step exchanges (postgres SSLRequest then Startup, LDAP bind then search, DNS-over-TCP length prefix); (c) binary reply parsing that is not regex-able: SNMP BER, SMB2 negotiate (spec says "from the 3B SMB probe's parser"), MongoDB BSON, Kafka, LDAP. Add a `parser` field naming a code parser (SMB, SNMP, ASN.1 lengths), or cut those probes. Also `protocol` lists `null` as if it were a protocol and matches have no protocol field; the null probe and speak-first services (ssh, ftp, ...) are probes with empty `send`, so say whether they cost a connect each in the ladder (they must not). Specify `$` escaping in replacements (a literal `$` in `detail`), `^`/`$` multiline semantics, and that regexes get a match deadline or length-bounded input (4096-byte replies from a hostile LAN device plus author regexes is a ReDoS surface on the main app's IO threads).

6. BLOCKING, Sec 7 and Sec 4 cpe: attacker-controlled text reaches an outbound query. A banner `version` captured by `$1` becomes the CPE that drives the NVD lookup. Existing code guards with `SAFE_VERSION` and a vetted product map (Cpe.kt, `forService` lines 11-21). "Prefers the match's cpe over the map" bypasses both. Also the sample CPE `cpe:2.3:a:redis:redis:$1` is not a valid 2.3 string (13 fields) and the existing templates use `{v}` not `$1`. Require: cpe is a template using `{v}` only; version goes through `SAFE_VERSION` before substitution; cpe string validated at load; a probe cannot supply a free CPE.

7. BLOCKING, Sec 7 identity integration. (a) Generated weight-60 rules from http_stacks set vendor, model and type; generic stacks (nginx, Apache, Express, Werkzeug, Tomcat, Grafana, Plex, Portainer, Pi-hole) are software not devices. Plex on a NAS sets nothing useful; Pi-hole on a Synology host and Proxmox running containers produce ties at weight 60 resolved by file order (`w > slot.weight`, DeviceIdentifier.kt:58 keeps the first). Only device-defining stacks (Hikvision, FRITZ!Box, Hue, Shelly, UniFi, printers) may set vendor/model/type; everything else must feed the existing `software` slot ("Runs ..."). Require a `role` field (`device` or `software`) and forbid type on `software`. (b) `ServiceMerge` never erases, so after an IP is reassigned or a service changes name, `stack`, `cpe` and `probe` stay (ServiceMerge.kt:226-229) and keep feeding identity at weight 60: "Home Assistant" sticks to what is now a printer. Require: when the fresh name differs from stored, clear `product`, `version`, `stack`, `cpe`, `probe`. (c) `stack` is "regex over the stacks of all ports" but `PORT_FIELDS` needs the new name registered in DeviceIdentifier.kt:20 and `ServiceInfo` mapping; name this edit.

## MINOR

8. MINOR, Sec 3 step 1. Null probe "waits 1000 ms" always; today `BannerReader` returns early on the first newline when nothing was sent (BannerReader.kt:34). Keep that early exit, or every silent port pays a full second. Also define tcpwrapped (accept then immediate close/RST): currently indistinguishable from "closed under us", and "refused connect ends the ladder" must not delete the port or lower confidence.

9. MINOR, Sec 3 step 3 soft matches. Nmap narrows by the service names a probe can match, not by the probe's own `service` field; yours is a single string so a `ssl`/`http` soft hit cannot select the right probe family. Also rarity is unusable with a cap of six: define the default intensity and say which probes actually get reached, otherwise the rare 25 are dead data.

10. MINOR, Sec 5 HTTP rules. Missing: AND conditions (Server and title), negative patterns (the existing file has `negativeSample`, Sec 5 drops it, so the 31 rules lose their negative tests), status/port conditions, `version` as a field (only mentioned in prose), `hard`/`soft`. "First hard hit wins" has no hard flag. `name` becomes `stack` but HttpFingerprintTool and `FingerprintRules` read `name`/`source`; list that migration in the plan. "At most three paths per rule" conflicts with `maxPaths` 3 per port; with about 15 path-only rules, which three are spent on a host that matches none is undefined and most hosts waste all three. Define selection (rules whose cheap tier hit first, `path`-only rules only when the port is already HTTP and the tier-1 result is generic).

11. MINOR, Sec 5 favicon. "MurmurHash3 as Shodan publishes" is over base64 of the file with a newline every 76 characters, signed 32-bit. Say so and add a known-vector test; otherwise a wrong hash is silent. It is also a fifth request (binary, size-capped) and is not counted in `maxPaths`. Cap bytes (64 KB) and follow no redirects.

12. MINOR, Sec 5 paths. `/api/`, `/admin/`, `/api2/json/version` against Proxmox/Synology/qBittorrent/arr services without credentials produce 401 counters in their auth logs; acceptable, but GET paths must be a reviewed allow-list of idempotent endpoints, and the doc should say so rather than "read-only" by assumption.

13. MINOR, Sec 6. Fragile list is self-contradictory: industrial ports are "null probe only" yet "except their own careful probe"; S7 102 and EtherNet/IP 44818 have none. The null probe itself consumes one of a PLC's few connections. Make the industrial rule "no connect at all unless hinted careful probe exists", and list 587/2222 (already SPEAKS_FIRST, ServiceIdentifier.kt:20) consistently with 25/110/143.

14. MINOR, Sec 3 Quick. Quick now sends active bytes (HEAD, DNS, SNMP) while Sec 2 and `ProbeModes.forProfile` define Quick as passive (ActiveProbeBudget.kt:196), and the Quick-all pass is run against every host on the LAN. That is a behaviour change to the most frequently run scan, defaulted on. Require default OFF for Quick (switch applies to Full/Custom only), or drop the Quick budget numbers (O3 is a blocking-sized open item); and add a Mode or ProbeMode.Quick variant instead of overloading Active.

15. MINOR, Sec 8 manual tool. A new `ToolId`, `FindingKind` values and applicability entries are needed (ToolId.kt:11-14, 17-20), the 3B `Tool` result is a findings list, while "writes its result to the port row as a scan would" needs a ServiceMerge call the tool framework does not have; name the interface. The tool takes `HostBusyRegistry.TOOL` (HostBusyRegistry.kt) so the ladder's "never while a tool runs" check must not deadlock the tool's own ladder. "Fresh budget regardless of settings" means the Settings switch off does not stop the tool: fine, say so. Two tool runs on the same port concurrently: undefined.

16. MINOR, Sec 10 tests. Holes: no test that a hostile reply (huge, binary, slow-loris) is bounded in time and memory; no test for Stop mid-TLS-handshake; no test that stale `stack` is cleared; no test that every `careful` probe is unreachable from the unhinted ladder; no negative samples for probe matches (a sample proves a hit, not a false positive); `ServiceProbesDeviceTest` uses a loopback server that cannot show real-device hangs, so the Director's LAN QA is the only real safety evidence and must list the fragile devices (printer, camera, Hue, ESP devices) explicitly, with a rollback switch (the Settings toggle) documented.
