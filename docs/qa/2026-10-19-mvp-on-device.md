## Defects found (ranked)

1. D1 (Medium) Hue Bridge on 10.0.4.20 appears in the home-network list among 10.0.3.0/24 hosts, with a MAC (ec:b5:fa:31:7a:a9) that cannot have come from the neighbour table (different subnet). It counts in "13 shown". Repro: Scan on 10.0.3.0/24 with a Hue Bridge on another subnet advertising mDNS; row "Hue Bridge - 317AA9, 10.0.4.20" is listed. Expected: excluded, or clearly flagged as off-subnet.
2. D2 (Medium) Granting location permission changes the network signature (adds SSID/BSSID), so all hosts, marks and notes recorded before the grant disappear ("No devices found yet"; Interesting filter empty). Repro: mark a host, `adb shell pm grant com.northwalessolutions.netprobe android.permission.ACCESS_FINE_LOCATION`, relaunch. Expected: annotations carry over, or a migration from the gateway+prefix signature.
3. D3 (Low) The phone's own address (10.0.3.242) is listed as "Unknown device". Should be labelled "This device" or excluded.
4. D4 (Low) Wi-Fi name is only obtainable via a button in Settings; Home shows a bare "Wi-Fi" with no hint to grant location.
5. D5 (Low) NAS (Synology DS220+) uses the generic desktop icon; no storage/NAS mapping.
6. D6 (Low) Router identity line reads only "Ubiquiti" although evidence says "UniFi Security Gateway"; model not surfaced. Pi-hole shows as two rows (.170 "pi.hole" and .234, sharing MAC e4:5f:01:e4:22:dc); the .234 row has only a bare IP title.
7. D7 (Info) Full scan on CHNAS reports 3261, 3263, 3264, 3265, 39694, 50001, 50002 as open "Unknown" ports; not verified as real services.
